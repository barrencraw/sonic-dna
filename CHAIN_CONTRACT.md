# SonicDNA Chain Contract: DNA Batch Parsing

This contract defines the triggers, inputs, terminal states, invariants, error taxonomy, idempotency strategy, atomicity boundaries, and required logs for the DNA Batch Parsing chain.

## 1. Trigger
- The Watcher in `main.py` detects changes in `data/raw/toSequence.txt` and calls `run_batch(correlation_id)`.
- Or, running `python main.py --once` calls `run_batch(correlation_id)` directly for a single batch run.

## 2. Inputs
- `data/raw/toSequence.txt`: A plain text file containing DNA sequences, one per line.

## 3. Terminal States
- **`SUCCESS`**: All new (non-deduplicated) DNA sequences have been successfully parsed, their results added to JSON and CSV cumulative output files, and their terminal state persisted in `processed_ledger.json`. The input file `toSequence.txt` is cleared.
- **`NO_NEW_ITEMS`**: All DNA sequences in the input file were already in the ledger (or the file was empty). No processing, side-effects, or writes occur on the ledger or output files. The input file is cleared.
- **`FAILURE`**: A typed processing or persistence exception is raised. No files are committed/updated in a corrupted state, and the input file is NOT cleared.

## 4. Invariants
- **Idempotency**: DNA sequences that already have a terminal outcome in the ledger are never re-processed.
- **Backwards Compatibility**: Output datasets (JSON and CSV) must support both `dna` and the canonical `dna_sequence` keys/headers.
- **No Torn Writes**: If writing outputs or the ledger fails (e.g. disk full, permission denied), no partial/corrupt files are left, and the pre-existing outputs remain unchanged.
- **Zero Idle Writes**: JSON, CSV, and ledger output files are completely untouched and no filesystem write or rename operations occur when all inputs are deduplicated (i.e. zero new items).

## 5. Error Taxonomy
The following custom exception taxonomy is defined under `utils/dna_ui.py`:
- `DNAProcessingError(Exception)`: Root base exception for all DNA parsing and execution failures.
  - `RuleLoadError(DNAProcessingError)`: Raised when rules cannot be loaded or initialized.
  - `InputReadError(DNAProcessingError)`: Raised when reading the input file `toSequence.txt` fails.
  - `PersistenceError(DNAProcessingError)`: Root base class for write or storage failures.
    - `LedgerLoadError(PersistenceError)`: Raised when loading the ledger fails due to corruption (invalid JSON).
    - `LedgerSaveError(PersistenceError)`: Raised when writing/moving the ledger file fails atomically.
    - `AtomicWriteError(PersistenceError)`: Raised when writing JSON or CSV output files fails atomically.

## 6. Idempotency Strategy
- **Idempotency Key**: The raw DNA sequence string itself.
- **Ledger Entries**: Persisted in `data/processed_ledger.json` using the lowercase `DNAStatus` string enum as the `terminal_outcome` field (values: `'success'`, `'error'`, `'skipped'`, `'refused'`).

## 7. Atomicity Boundaries
- **Ledger Writes**: Writing to `processed_ledger.json` uses a temporary file, flushes/syncs to physical storage, and performs an atomic rename (`os.replace`).
- **Output Writes**: Writing to `toSequence_parsed.json` and `toSequence_parsed.csv` uses a temporary directory, flushes and syncs individual files, and atomically renames them to their final destination only after all writes complete.
- **Input File Drainage**: The input file `toSequence.txt` is cleared only after `run_batch()` completes successfully without any exceptions.

## 8. Required Logs (Structured Telemetry)
All crucial operations emit a single-line JSON log prefixed with `JSON_LOG:` with the following schema:
- `timestamp`: UTC ISO 8601 string.
- `correlation_id`: ID of the transaction/batch, or `"N/A"`.
- `actor_id`: `"sonicdna_system"`.
- `chain_name`: `"dna_batch_parsing_chain"`.
- `step`: Identifier of the progress step (e.g., `"batch_start"`, `"deduplicated"`, `"parsed"`, `"batch_end"`, `"cleanup_failure"`).
- `outcome`: State representation (e.g., `'success'`, `'error'`, `'skipped'`).
- `latency_ms`: Duration of the step or batch execution in milliseconds, or `0`.
- `idempotency_key`: DNA sequence string being evaluated, or `"N/A"`.
- `outcome_detail`: Detailed outcome message, or `"N/A"`.

## 9. Telemetry & Grep Recipes

To extract, inspect, and analyze structured logs generated by the batch parsing chain:

### Extract all structured logs:
```bash
grep "JSON_LOG:" stdout.log
```

### Format and query logs with jq:
```bash
grep "JSON_LOG:" stdout.log | sed 's/^JSON_LOG: //' | jq .
```

### Filter for errors or warnings:
```bash
grep "JSON_LOG:" stdout.log | sed 's/^JSON_LOG: //' | jq 'select(.outcome == "error")'
```

### Track step lifecycle of a specific DNA sequence:
```bash
grep "JSON_LOG:" stdout.log | sed 's/^JSON_LOG: //' | jq 'select(.idempotency_key == "VOL08900750712")'
```
